# Kubernetes 仿真平台工作总结

我们将现有网络仿真平台（SEED Emulator）扩展到 Kubernetes，形成了从拓扑编译、集群准备、镜像构建、工作负载部署到环境清理的完整流程。原先围绕单机容器运行的仿真，现在可以部署到本机虚拟机集群、已有物理机集群，以及分布在多台物理宿主机上的虚拟机集群。

## 建立分层的部署流程

我们把“生成仿真工作负载”和“准备运行环境”分成独立阶段。编译阶段读取已构建好的仿真拓扑，将网络、路由器、终端主机等对象转换为 Kubernetes 工作负载、网络定义和容器镜像构建材料。编译结果不包含真实集群的节点地址、镜像仓库地址或机器放置方式，因此同一份拓扑产物可以用于不同的部署环境。

集群准备阶段根据所选环境创建或接入计算节点，安装轻量级 Kubernetes 发行版 K3s，配置节点间的管理连接、镜像仓库和网络组件，并保存后续部署与清理需要的状态。运行阶段再把镜像构建并推送到集群可访问的仓库，将通用编译结果适配到实际环境，部署仿真工作负载并等待其就绪。这种分层使拓扑修改、集群维护和工作负载重跑可以分别处理。

## 实现多网卡仿真网络

我们将 Kubernetes 的管理网络与仿真网络分开：默认网卡承载集群通信，Multus 负责为仿真节点附加额外网卡。每条仿真网络对应独立的网络定义，仿真节点的地址沿用原拓扑中的静态地址。容器启动时还会恢复接口命名、链路时延、带宽、丢包和必要的系统网络参数，以保持仿真行为与拓扑设定一致。

主要的数据面采用 macvlan 与 VLAN。不同仿真网络分配不同 VLAN，避免同一底层网络中的流量相互混杂。我们同时保留 Kube-OVN 路径，以支持需要 OVN 逻辑网络的部署。对于跨物理宿主机的场景，我们增加桥接和 VXLAN 扩展，使位于不同机器、但属于同一仿真网络的工作负载能够进行二层通信。

## 支持三种集群底座

- **本机虚拟化：** 自动规划控制节点和工作节点的计算、内存、磁盘、地址与名称；准备虚拟机管理网络，并支持为虚拟机附加额外的二层网络。
- **已有物理机：** 使用指定的机器建立集群，检查远程登录和管理权限，并根据部署配置准备跨节点的桥接与 VXLAN 网络。
- **多宿主机虚拟化：** 在不同物理宿主机上分配虚拟机与独立的管理子网，建立跨宿主机路由；为仿真网络配置专用 VLAN 网卡和跨宿主机二层连接。

我们为虚拟机资源增加了清晰的内存单位输入和统一换算，减少不同部署方式之间的配置歧义。对多宿主机网络还加入了部署前检查：验证同一 VLAN 的双向连通，并确认相邻 VLAN 之间保持隔离。

## 完善部署和清理闭环

部署前会检查集群节点、镜像仓库、容器构建能力和必要的网络条件。部署时，系统依据实际集群配置修改网络父接口和最大传输单元（MTU），准备 VLAN 子接口，构建并发布镜像，然后应用工作负载并等待就绪。这使一份通用的编译结果能够适配不同机器上的网卡和网络封装方式。

清理流程区分工作负载与底层环境：可以只移除仿真工作负载，保留集群以便快速重跑；也可以根据保存的部署状态卸载集群组件，并清理工具创建的虚拟机和网络资源。对于已有物理机，清理针对安装的集群及网络组件，不删除物理机器。

## 降低配置和验证成本

我们提供了面向对象的部署配置生成方式。使用者可以通过独立的配置对象描述节点、虚拟机资源和网络选项，再生成集群准备所需的配置。网络类型只需在一个接口中指定，相关的容器网络接口（CNI）字段由配置对象推导；生成配置本身不会触发集群操作。

我们建立了覆盖编译产物的自动检查，验证资源结构、镜像构建材料、网络定义、静态地址、拓扑元数据及多种部署方式的渲染结果，并将这些检查接入持续集成。随后还完成了三种集群底座的端到端运行与清理验证，检查了跨节点双向通信。
